## 共用规则

整个专案都先遵守：

* 使用 SwiftUI。
* 最低支援 iOS 17。
* 优先使用较新的 SwiftUI 写法，例如 `NavigationStack`、`@Observable`。
* 不随便加入第三方套件、登入、后端、云端同步或外部 API。
* AI 如果发现功能太难、需求互相冲突、需要额外权限或服务，必须先说明，不可以自己偷偷加。
* 每完成一个开发阶段，都要能 build、实际操作、再 commit。


## 第一步：体验设计层
> 把 App 想清楚

### 这一步要做什么？

先从使用者角度想 App，不谈程式码。

你要描述：

* 谁会用这个 App？
* 他在什么情况下打开？
* 他想完成什么？
* 他操作后应该看到什么结果？
* App 大概需要哪些画面？

这一步会得到：

* user flow
* 低保真 UI
* 完整功能想法
* 可能的困难与限制

### 给 AI 的 prompt (Chatgpt, Deepseek, Claude ...)

```text
你是一位协助学生规划 Swift App 的产品与使用者体验助手。

我的任务是把一个 App 想法具体化。
你不要直接写程式，也不要先讨论技术架构。

请先透过对话帮我厘清：

- 谁会使用这个 App？
- 使用者在什么情况下打开它？
- 他最想完成什么？
- 他操作时会经过哪些步骤？
- 他最后应该看到什么结果？
- 这个 App 需要哪些主要画面？

规则：

1. 一次最多问 2 到 4 个问题。
2. 问题请用日常语言，不要使用太多技术术语。
3. 如果我的想法太大或太模糊，请帮我缩小、拆分或提供选项。
4. 请主动提醒我：
- 哪些功能可能很难做
- 哪些功能需要后端、登入、外部 API、权限或额外资料
- 哪些功能适合先简化
- 哪些需求之间可能冲突
5. 不要自己替我加功能。
6. 每次我回答后，先简短整理你的理解，再继续提问。

资讯足够后，请整理成：

1. App 的一句话介绍
2. 使用者与使用情境
3. 主要使用者流程
4. 低保真 UI
- 每个画面看到什么
- 可以做什么
- 操作后会发生什么
5. 完整功能清单
6. 可能的难点、限制与简化建议
7. 还需要我确认的问题

我的初始想法是：

【这里写入你们当前的想法】
```

### 期待产出

例如：

* 使用者打开 App 后先看到什么。
* 他要按哪些按钮。
* App 有哪些主要页面。
* 每个页面负责什么。
* 哪些功能可以做。
* 哪些功能可能需要后端、帐号、权限或额外资料。
* 哪些部分应先简化。

### 自己检查

进下一步前，问自己：

* 我能不能清楚讲出使用者怎么使用这个 App？
* 我能不能说明每个主要画面是做什么的？
* 我有没有知道哪些功能最麻烦？
* AI 有没有偷偷加我没想要的功能？
* 我的想法有没有还很模糊或互相冲突的地方？


## 第二步：系统规划层
> 让 AI 规划 App 怎么做

### 这一步要做什么？

让 AI 把**第一步**内容翻译成：

* App 要管理哪些资料。
* 每个画面要读取或修改什么资料。
* 资料怎么流动。
* 程式档案怎么分。
* 整个专案要分几个阶段完成。

这一步不写程式。

### 给 AI 的 prompt

```text
你是一位 SwiftUI App 的系统规划助手。

以下内容是已经确认过的 App 想法、user flow 和低保真 UI。

请帮我把它整理成适合初学者理解的小型 SwiftUI 专案规划。

技术规则：

- 使用 SwiftUI。
- 最低支援 iOS 17。
- 使用较新的 SwiftUI 写法，例如 NavigationStack、@Observable。
- 不使用第三方套件。
- 不自行加入登入、后端、云端同步、外部 API 或其他我没有要求的功能。
- 不要开始写实际程式码。
- 如果需求有技术难点、矛盾或隐藏成本，请先指出。

请整理成以下内容：

1. 核心资料
- App 需要记住哪些资料？ 
- 每种资料有哪些栏位？ 
- 哪些资料关掉 App 后还要保留？

2. 画面责任
- 每个画面显示什么？ 
- 使用者能做什么？ 
- 它会读取或修改哪些资料？

3. 资料与操作流
- 资料由谁管理？ 
- 使用者按按钮后，资料怎么改？ 
- 哪些画面会跟着更新？

4. 最小档案结构
- Models
- Stores
- Views
- Services
请列出主要档案与用途。

5. 开发阶段规划
- 拆成 4 到 6 个阶段。 
- 每个阶段完成后，都要能在模拟器展示一个具体成果。 
- 每个阶段都要列出：
- 这次完成什么
- 不做什么
- 怎么验收

6. 难点与风险
- 哪些功能实作成本高？ 
- 哪些地方可能需要重新确认？ 
- 哪些功能建议先简化？

以下是第一步确认的内容：

【贴上第一步的输出】
```

### 期待产出

你应该能看懂：

* App 里最重要的资料是什么。
* 每个画面大概负责什么。
* 使用者按下按钮后，资料怎么更新。
* 专案会有哪些主要档案。
* 开发顺序是什么。
* 哪些部分可能做起来很麻烦。

### 自己检查

进下一步前，问自己：

* 我知不知道这个 App 要记住哪些资料？
* 我知不知道每个画面大概负责什么？
* 每个开发阶段结束后，是否都有能展示的成果？
* AI 有没有加入我没要求的复杂架构？
* AI 有没有指出真正需要注意的难点？
* 如果有难点，我是否已经决定要做、简化，还是暂时不做？

## 第三步：工程执行层
> 逐步让 AI 写程式

### 这一步要做什么？

这一步才开始写 code。

不要一次要求 AI 完成整个 App。

每次只做一个开发阶段：

1. 先确认本次要完成什么。
2. 让 AI 根据目前 repo 产生具体 coding prompt。
3. 交给 coding agent 实作。
4. Build。
5. 在模拟器操作。
6. Commit。
7. 再进下一阶段。


### 先让 AI 产生 coding prompt (每次具体发给ai写代码的文本)

```text
你是一位 SwiftUI 工程规划助手。

目前专案已完成：

【贴上目前已完成的功能】

目前要做的开发阶段是：

【贴上本阶段目标、限制与验收条件】

请先读取目前 repo 的真实档案结构与既有 code，
再产生一份给 coding agent 使用的详细实作 prompt。

技术规则：

- 使用 SwiftUI。
- 最低支援 iOS 17。
- 使用 NavigationStack、@Observable 等较新的 SwiftUI 写法。
- 不使用第三方套件。
- 不主动加入新功能。
- 不重构和本次任务无关的 code。
- 如果目前 repo 和原规划不同，请先说明差异，再提出最小修改方案。
- 不要直接写 code，只产生 coding prompt。

coding prompt 必须包含：

1. 目前 repo 状态
2. 本次唯一目标
3. 要新增哪些档案
4. 要修改哪些档案
5. 每个档案具体要做什么
6. 这次明确不做什么
7. build 与验收条件
8. 完成后要回报什么
```

### 每次AI完成后要做什么？

不要只相信 AI 的回覆。

你要自己：

* Build 专案。
* 打开模拟器。
* 走一次本次要完成的使用者流程。
* 确认结果和原本的 user flow 一样。
* 看 AI 有没有多做不需要的功能。
* Commit 目前可用版本。

### 自己检查

每完成一个阶段，问自己：

* App 可以 build 吗？
* 我能不能真的走完本次的使用者流程？
* 结果是不是我原本想要的？
* AI 有没有改坏原本能用的东西？
* AI 有没有偷偷加功能？
* 我是否已经 commit？
* 下一步要做什么，我是否清楚？


## 最后记住这三句话

* 第一步：使用者要怎么用？ 
* 第二步：这个 App 要怎么组成？ 
* 第三步：现在这一步要改哪些 code？ 

不要一开始就叫 AI 完成整个 App。

每次只确认一件事、完成一小步、实际验收，再往下走。
